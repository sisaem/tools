CSV 한글 깨짐, 맥에서 온 파일명, 그리고 JSON·Base64가 필요한 순간

문서 정리 도구와 유틸리티 도구가 쓰이는 상황은 대개 '파일을 다른 프로그램으로 옮겼더니 이상해졌다'입니다. 자주 만나는 경우를 원인부터 정리했습니다.

CSV를 엑셀에서 열면 한글이 깨진다

웹 서비스에서 내려받은 CSV 파일을 엑셀에서 더블클릭해 열면 한글이 ì•ˆë…• 같은 글자로 깨지는 일이 흔합니다. 원인은 문자 인코딩의 불일치입니다. 요즘 웹 서비스는 CSV를 UTF-8로 저장하는데, 한국어 윈도우의 엑셀은 별다른 표시가 없는 CSV를 예전 방식인 CP949(EUC-KR)로 읽으려 합니다.

해결 방법은 두 가지입니다.

  1. 파일 맨 앞에 UTF-8 표시(BOM)를 넣는다. 엑셀은 이 표시를 보면 UTF-8로 읽습니다. 이 사이트의 문서 정리 도구에서 내려받는 CSV에는 이 표시가 들어 있어서 엑셀에서 바로 열립니다.
  2. 엑셀의 가져오기 기능을 쓴다. 빈 통합 문서에서 데이터 → 텍스트/CSV에서를 고르고, 파일 원본을 65001: 유니코드(UTF-8)로 지정하면 됩니다.

반대로 엑셀에서 "CSV(쉼표로 분리)"로 저장한 파일을 다른 시스템에 올렸더니 한글이 깨진다면, 엑셀이 CP949로 저장했기 때문입니다. 저장할 때 CSV UTF-8(쉼표로 분리) 형식을 고르세요.

우편번호와 전화번호의 앞자리 0이 사라진다

CSV를 엑셀에서 열면 01012345678이 1012345678로, 우편번호 06236이 6236으로 바뀝니다. 엑셀이 숫자처럼 보이는 값을 숫자로 바꾸면서 앞의 0을 버리기 때문입니다. 사원번호, 계좌번호, 제품 코드처럼 '숫자 모양의 글자'도 같은 일을 겪고, 15자리가 넘는 번호는 뒷자리가 0으로 바뀌기까지 합니다.

한번 열어서 저장해 버리면 원래 값은 복구할 수 없습니다. 이런 열이 있는 CSV는 더블클릭으로 열지 말고, 위의 가져오기 기능에서 해당 열의 형식을 텍스트로 지정한 뒤 불러오세요. 내용 확인만 할 거라면 이 사이트의 CSV 표 변환에 붙여 넣어 표로 보는 방법도 있습니다. 브라우저에서 보여 주기만 하므로 값이 바뀌지 않습니다.

쉼표가 들어간 값

CSV는 쉼표로 칸을 나누기 때문에, 값 안에 쉼표가 있으면(서울시 강남구, 101호) 그 값을 큰따옴표로 감싸야 합니다. 감싸지 않은 CSV를 열면 칸이 하나씩 밀립니다. 직접 CSV를 만들어 다른 곳에 넘길 때는 주소, 금액(1,000), 메모처럼 쉼표가 들어갈 수 있는 칸을 따옴표로 감싸 두세요.

맥에서 온 한글 파일 이름이 'ㅎㅏㄴㄱㅡㄹ'로 보인다

맥에서 만든 파일을 윈도우로 옮기거나, 맥 사용자가 웹에 올린 파일을 윈도우에서 내려받으면 파일 이름의 한글이 자음과 모음으로 풀어져 보이는 경우가 있습니다. 맥은 한글을 자모를 나눈 형태(NFD)로 저장하고, 윈도우는 완성된 글자(NFC)로 다루기 때문입니다. 보기에만 이상한 게 아니라 파일 이름 검색이 안 되거나, 같은 이름의 파일이 두 개처럼 보이기도 합니다.

이 사이트의 파일명 정리 기능은 결과를 완성형(NFC)으로 바꿔서 보여 줍니다. 풀어진 파일 이름 목록을 붙여 넣으면 정상적인 이름을 얻을 수 있고, 그 이름으로 파일을 다시 바꾸면 됩니다. 파일이 많다면 결과를 CSV로 받아 일괄 이름 바꾸기 프로그램에 넣어 쓰면 됩니다.

마크다운은 어디에 쓰나

마크다운은 # 제목, - 목록, **굵게**처럼 기호로 서식을 표시하는 글쓰기 방식입니다. 깃허브, 노션, 슬랙, 여러 사내 위키가 이 방식을 씁니다. 문서 정리 도구의 마크다운 변환은 마크다운을 HTML로 바꿔 미리 보여 주므로, 메일 본문이나 웹 게시판에 서식 있는 글을 붙여 넣어야 할 때 쓸 수 있습니다.

두 글을 비교해야 할 때

계약서 수정본을 받았는데 어디가 바뀌었는지 표시가 없을 때, 같은 공지문의 두 버전 중 어느 것이 최신인지 헷갈릴 때 문자열 비교를 씁니다. 두 글을 줄 단위로 비교해서 추가된 줄과 삭제된 줄을 색으로 보여 줍니다. 한 문단 안에서 한 단어만 바뀌어도 그 줄 전체가 바뀐 것으로 표시되므로, 긴 문단은 문장마다 줄을 바꾼 뒤 비교하면 차이가 더 잘 보입니다.

URL 인코딩: 주소 속 %ED%95%9C의 정체

한글이 들어간 주소를 복사해서 붙이면 https://example.com/%ED%95%9C%EA%B8%80처럼 바뀌어 있는 걸 볼 수 있습니다. 주소에는 영문과 일부 기호만 쓸 수 있어서, 한글을 UTF-8 바이트로 바꾼 뒤 %를 붙여 적은 것입니다. %ED%95%9C가 '한'입니다. 유틸리티 도구의 URL 변환에 넣으면 원래 한글로 되돌려 볼 수 있습니다. 메일이나 보고서에 링크를 적을 때 이 형태로 적혀 있으면 어떤 페이지인지 알 수 없으니, 풀어서 확인하는 데 씁니다.

Base64는 암호가 아니다

Base64는 그림이나 파일 같은 데이터를 영문과 숫자로만 이루어진 글자로 바꾸는 방식입니다. 이메일 첨부 파일, 웹 페이지 안에 직접 넣은 작은 그림, 일부 설정 파일에서 쓰입니다. 겉보기에는 알아볼 수 없는 문자열이라 암호처럼 보이지만, 누구나 그대로 되돌릴 수 있는 변환일 뿐입니다. 비밀번호나 개인정보를 Base64로 바꿔 두었다고 안전해지지 않는다는 점을 기억하세요.

JSON 정리는 누가 쓰나

JSON은 프로그램끼리 데이터를 주고받을 때 쓰는 형식입니다. 개발자가 아니어도 업무 시스템에서 데이터를 내보내기 했더니 JSON 파일이 나오거나, 오류 메시지에 긴 JSON이 한 줄로 붙어 있는 경우가 있습니다. JSON 정리에 붙여 넣으면 들여쓰기를 해서 구조를 읽기 쉽게 보여 주고, 형식이 틀렸으면 어디가 틀렸는지 알려 줍니다.

임시 비밀번호와 UUID

임시 비밀번호 생성은 브라우저의 암호학적 난수 기능(crypto.getRandomValues)으로 만듭니다. 새 계정의 초기 비밀번호나, PDF에 걸 암호를 만들 때 쓸 수 있습니다. UUID는 겹치지 않는 고유한 식별 번호가 필요할 때(장비 관리 번호, 테스트용 데이터 등) 씁니다.
